# Figma 만들기

디자인 시스템(코드)에서 Figma 디자인 파일을 만든다. 사람이 Figma를 그리지 않는다. Storybook에 그려진 컴포넌트를 상태별로 읽어 Figma 컴포넌트로 옮기고, 색·간격·모서리는 SLDS hook과 같은 이름의 Figma 변수에 묶는다. 만든 Figma의 문서 프레임은 그대로 PDF로 내보내 외부 제출용 디자인 문서가 된다.

## 만들어지는 Figma가 지키는 세 가지

[밀버스 Figma 작성 규칙](https://github.com/Milvus-Wina/milvus-design-system/blob/main/templates/docs/milvus/figma.md)의 1장 체크리스트와 같다.

- **상태 전부.** 누르거나 입력하는 요소가 있는 컴포넌트는 `Default · Hover · Pressed · Focus · Disabled`를 모두 만든다. Storybook 화면에서 Chrome이 상태를 강제로 켜고 읽은 모양이다. 누르는 요소가 없는 컴포넌트(Badge, Spinner 등)는 문서에 **"상태 없음(의도)"**으로 적는다
- **값은 전부 역할 변수.** 색·여백·모서리·글자 크기·테두리 두께는 `color/accent-container/1`, `spacing/4`, `radius/pill`처럼 hook 이름과 1:1인 변수에 묶는다. 같은 값의 변수가 없는 값은 직접 값으로 남기고, 문서 프레임에 **"변수가 없는 직접 값 N건"**으로 센다
- **모든 프레임에 자동 레이아웃.** 화면의 flex 방향·간격·정렬을 그대로 옮긴다. 이미지나 SVG 통째가 아니라 편집할 수 있는 레이어다(아이콘만 SVG 벡터)

## 준비

- **Figma 데스크톱 앱.** 웹에서는 개발 플러그인이 실행되지 않는다. 무료(Starter) 플랜으로 된다
- **Google Chrome.** 디자인 시스템 저장소에서 Storybook을 읽을 때만 필요하다(백그라운드로 열린다)
- Figma 파일은 **Drafts에 새로 만든 빈 파일**에서 시작한다. 운영 파일에서 돌리지 않는다

## 고객 프로젝트에서

```bash
pnpm milvus figma --name 고객사이름
```

프로젝트의 브랜드(BrandingSet의 `BRAND_COLOR`, `milvusBrand.css`)로 변수 값을 만들고, 플러그인과 작성 데이터를 `.milvus/figma/`에 둔다. 컴포넌트 모양은 패키지에 든 밀버스 기본 브랜드의 Storybook 읽기 결과를 쓰는데, 값이 변수 이름으로 저장돼 있어서 **색은 프로젝트 브랜드로 바뀐다**. 모서리·높이처럼 `milvusBrand.css`로 바꾼 모양까지 반영하려면 아래 저장소 방식으로 그 브랜드를 다시 읽는다.

1. Figma 데스크톱 → **플러그인 → 개발 → 매니페스트에서 플러그인 가져오기…** → `.milvus/figma/manifest.json` (처음 한 번)
2. **플러그인 → 개발 → Milvus Design System → 디자인 시스템 생성 (figma-data.json)** → `.milvus/figma/figma-data.json` 선택
3. 창 로그가 `완료: 컴포넌트 ○개, 직접 값 ○건, noCapture 0, unbound 0`이면 끝이다. 컴포넌트가 많아 몇 분 걸린다
4. 다시 실행하면 새로 만들지 않고 갱신한다. 페이지·섹션·변수가 늘지 않는다

## 코드에서 옮기기 (component · page)

초기 세팅(위)이 끝난 Figma 파일에 **프로젝트에서 만든 LWC와 FlexiPage만** 옮긴다. 디자인은 코드에서 끝내고 Figma는 결과를 담는다. 화면을 렌더링하지 않고 코드를 읽으므로 Chrome·Storybook이 필요 없고, Figma MCP를 쓰지 않아 무료 플랜 한도와 무관하다.

```bash
pnpm milvus figma
```

`1) 초기 세팅 2) component 3) page`를 묻고, 이름을 쉼표로 받는다. 한 줄로도 된다.

```bash
pnpm milvus figma --component acmeSummary,acmeHeader
```

```bash
pnpm milvus figma --page Account_Record_Page
```

`.milvus/figma/figma-update.json`이 생기면 **플러그인 → 개발 → Milvus Design System → 선택한 것만 반영 (figma-update.json)** 에서 고른다. 고른 것만 지우고 다시 그리고, 나머지는 그대로 둔다.

page는 FlexiPage XML(`force-app/…/flexipages/<이름>.flexipage-meta.xml`. org에만 있으면 `sf project retrieve start -m FlexiPage:<이름>`)을 읽는다.

- 프레임은 데스크톱 1440px. 영역(header·main·sidebar 등)은 템플릿 태그별 폭(아래 표)으로 나눈다. 표에 없는 템플릿은 영역을 한 열로 쌓고 알린다
- 영역 안은 XML 순서대로 위에서 아래로. 탭 묶음은 탭 이름 줄과 활성 탭 내용만, 필드 묶음은 열로
- 프로젝트 LWC(`c:이름`)는 인스턴스, 표준 컴포넌트(하이라이트 패널, 관련 목록 등)는 코드가 없어 이름 붙인 자리 표시 상자
- 영역 폭은 메타데이터와 공식 문서(Lightning Page Templates)에 숫자가 없어 **org 화면(폭 1440)에서 잰 값**이다(2026-11-08, 개발 org). 페이지 여백 16(`spacing/4`), 영역 사이 12(`spacing/3`)

## 디자인 시스템 저장소에서(브랜드를 바꿔 다시 읽을 때)

`brands/<브랜드>/`의 `theme.json`·`util.css`를 고친 뒤 순서대로 실행한다. **한 번에 하나만** 돌린다. 둘이 겹치면 같은 `storybook-static` 폴더와 Chrome 포트를 써서 둘 다 깨진다.

```bash
pnpm build-storybook
node scripts/capture-storybook.ts --brand Slack
pnpm figma --brand Slack --name Slack --out figma-plugin/figma-data-slack.json
```

## hook을 바꾸면 Figma에 반영되는지 확인하기

같은 Figma 파일에 두 브랜드를 차례로 올려 비교한다. 예시 브랜드 `Slack`은 Figma 커뮤니티 파일 「Slack Design System and UI Kit」의 값을 옮긴 것이다(`brands/Slack/util.css` 주석에 출처와 옮기지 못한 값).

1. 빈 파일에 Milvus 작성 데이터(`figma-plugin/figma-data.json`)로 플러그인을 실행하고 위 표의 왼쪽 값을 확인한다. 버튼을 선택해 오른쪽 패널의 채우기·모서리가 **변수 이름**으로 보이는지도 본다
2. 같은 파일에 Slack 작성 데이터(`figma-plugin/figma-data-slack.json`)로 다시 실행한다
3. 변수 **이름은 그대로**이고 **값과 모양만** 오른쪽으로 바뀌면 통과다. Slack 데이터에 없는 컴포넌트도 색은 바뀐다(변수 값이 바뀌었으므로)
4. Storybook 툴바의 브랜드를 Slack으로 두고 같은 컴포넌트를 나란히 보면 Figma와 같은 모양이어야 한다

## 다른 Figma 파일의 값 가져오기

고객사 Figma나 커뮤니티 디자인 키트의 값으로 브랜드를 만들 때 쓴다.

- **플러그인 → 개발 → Milvus Design System → 이 파일의 변수·스타일 내보내기.** 그 파일의 변수·색·글자·효과 스타일과 선택한 노드(모서리·여백·그림자·연결된 변수 이름)를 JSON으로 받는다. 컴포넌트 모양도 필요하면 실행 전에 컴포넌트 세트를 선택한다. 커뮤니티 파일은 먼저 Drafts에 복제해야 플러그인이 돈다
- 플러그인을 쓸 수 없으면 Figma에서 섹션을 **SVG로 내보내도** 된다. 색(`fill`)·모서리(`rx`)·테두리·그림자(SVG 필터)가 정확한 값으로 들어 있다. 글자는 윤곽선으로 바뀌어 이름은 읽을 수 없다
- 받은 값으로 `brands/<브랜드>/util.css`를 쓰고 `pnpm test:brands`로 규칙(허용된 hook, 대비 4.5:1)을 확인한다

## 외부 제출용 PDF

각 페이지에서 Figma 메뉴 **파일 → 프레임을 PDF로 내보내기**. 섹션 안의 `Doc/…` 문서 프레임이 페이지마다 PDF 한 권이 된다.
